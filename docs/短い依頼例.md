# 短い依頼例

共通ルールはルートの [AGENTS.md](../AGENTS.md)、列仕様と実行手順は [施設追加手順](施設追加手順.md) にあります。毎回共通事項を貼り直す必要はありません。地域・テーマ・特別な重複方針・作業範囲だけ指定してください。

- 「東京のカプセルホテルを新資料化。チェーンは代表1件、既存施設は新資料にも収録。調査から公開まで。」
- 「資料17に東京都内の候補を追加。既存と同じ施設は除外。調査から公開まで。」（資料17の名前・CSVをregistryと照合して開始）
- 「資料『古いビル』の説明とWikipedia・関連リンクを全件監査し、確認できた対象項目を修正して公開。ID・行順は維持。」
- 「全国の団地商店街を候補調査。既存重複も表示。今回は報告のみ。」
- 「この施設を資料『地域文化施設』に必ず追加。不明な情報は空欄。公開まで。」
- 「資料『カプセルホテル』に5件追加。今回はローカル検証まで、commit・pushしない。」

通常の追加・編集依頼は調査、対象編集、生成、保全・件数・リンク・画面の検証、commit、mainへの反映、Actionsと公開確認まで進めます。「報告のみ」「pushしない」等の限定があればその範囲で終了します。通信・権限・競合で完了できない場合は実施済みと未完了を分けて報告します。

重複方針を省略した場合は既存重複を保持し、同一資料への単純な再追加は避けます。チェーンを代表1件に絞る、既存分類から移す、重複所属させる等は依頼ごとに指定してください。広すぎる地域・テーマでは調査範囲と採用理由を記録し、網羅性を未確認のまま保証しません。
